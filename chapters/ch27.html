一行 ES|QL 怎样变成结果表？竖杠先规定各命令的输入关系，分析器检查字段与类型，优化器再等价改写计划；Driver 把列式 Page 逐批传给算子。把查询语义、执行计划与响应形状分开，才能解释 WHERE 为什么可能没有独立过滤算子，以及 AVG 为什么先合并中间态再做除法。

27.1 管道规定语义，不钉死物理链

FROM tut-l27-pages | WHERE views > 100 | STATS avg(views) 读五篇，筛掉 50 与 100，再把 150、200、250 平均成 200。每个后续命令接收前一命令输出的表，竖杠表达的是输入依赖与结果语义。这与 Unix 管道有相似的阅读方式，但 ES|QL 会先建立完整计划，再分析、优化与分布式执行；没有为每个命令创建独立 OS 进程，也不保证一命令对应一个算子。

表可以有更多列或更多行。WHERE 丢行，KEEP 选列，SORT 改顺序，EVAL 可增加列；不能概括成“每个命令都把表变瘦”。本例无 BY，STATS 输出一行。A 组先验证均值与列名；再明确排序后 LIMIT 2、最后 STATS，得到 (250+200)/2=225。若 LIMIT 1 在 STATS 后，只限制结果行，仍得到 200。聚合处理的是到达它的输入集合，不是无条件处理原索引所有文档。

普通 FROM 查询未写 LIMIT 时默认返回 1000 行，通常最大输出 10000 行；两者可由集群设置改变。本课不修改它们，且不涉及 TS 的不同默认值。输出截断不把 STATS 的输入自动改成前 1000 篇；显式放在 STATS 前的 LIMIT 才属于主动改变输入语义。依据：普通FROM结果限制与配置。

27.2 三个命令怎样成为可执行计划

同步入口是 POST /_query，请求体的 query 是管道文本。REST 解析请求并交给动作层，不在路由函数里逐行算平均。POST /_esql 在本版返回 405：与裸索引路由 /{index} 发生方法冲突，allowed 含 GET、PUT、DELETE、HEAD；查询没有运行。GET /_query 与 GET /_query/async 也回 405，allowed 为 POST。后者只证明提交路径的方法冲突，不能替代一次真实异步查询及结果取回。

LogicalPlanBuilder 的 visitCompositeQuery 先解析左侧计划，再把它传给右侧 PlanFactory。普通索引 FROM 起于 UnresolvedRelation；WHERE 创建 Filter；本课 STATS 创建无分组的 Aggregate。分析阶段绑定索引字段与类型，概念上得到 Aggregate(Filter(EsRelation))。这只是核心结构，省略输出列、别名与结果限制等节点；时序索引的 STATS 有另一个分支。visitCompositeQuery。

AVG 接受本课的 long，不接受 keyword title；A14 的 400 verification_exception 在运行算子前拒绝。函数名称和命令关键字不区分大小写，未起别名的表达式列名保留文本，所以 avg(views) / AVG(views) 的值一样、列名不同。这条结论不能推广到字段标识符的大小写。

逻辑过滤规则把可移动的条件尽量提前；物理侧的 PushFiltersToSource 再分类条件，将可翻译部分合入数据源 query，剩余条件继续由 FilterExec 处理。它们是两处不同的工作。对本课 long 的 views > 100，profile 没有 FilterOperator 与下推源码相符，150/200/250 的结果也验证了边界；仅看到 LuceneSourceOperator 这个名字，不能读出其内部具体 range。PushFiltersToSource.rewrite。

profile 是本次执行证据。本轮真实输出含数据侧 INITIAL、最终 FINAL 与额外的 ExchangeSource → ExchangeSink 中转 Driver；不能规定“永远两条链”，也不能把 FilterOperator 缺席写成一切 WHERE 都可下推。版本、mapping、查询形状、并行度和优化路径都会影响算子描述。A11 保留完整 profile，先按 operator 识别职责，再看节点与 Driver 信息。

27.3 AVG 的分母究竟数什么

本课普通 long 字段的 AVG 在 Avg.surrogate 改写为 SUM(field) / COUNT(field)，结果类型 double。这里的 COUNT 是有效字段值数，不无条件等于文档数。五篇主数据每篇一个非空 views，因此过滤后 sum=600、count=3。若两个部分聚合分别为 150/1 与 450/2，必须合并为 600/3=200；直接平均两个局部均值会得到 187.5，丢掉了样本权重。Avg.surrogate。

C 组隔离四篇：views=10、views=[20,40]、缺失、显式 null。未配置 null_value，缺失与 null 不产生数值；有效值为 10/20/40，COUNT(views)=3，而 COUNT(*)=4。于是 AVG=70/3≈23.333333，而不是 70/4。单篇多值不是先算篇内均值再平均文档；分母与分子都计入有效值。CountAggregatorFunction有效值计数。

无 BY 的 AggregationOperator 在输入 finish 后才产出聚合结果。“阻塞”指输出等待输入结束，不表示把全部原始行一直留在内存；SUM / COUNT 可以逐页更新有限状态。INITIAL 输出中间态，FINAL 合并中间态，Eval 再做除法。真实状态还有有效性标志及类型信息，图中 600 / 3 是便于推导的数值摘要。空输入时，无分组 STATS 仍返回一行 AVG=null、COUNT(*)=0；实现不会拿普通 0/0 来代表结果。AggregationOperator阻塞语义。

这幅数据流图解释本课算术路径，省略中转 Driver、Project、Limit 等辅助算子。Exchange 连接不同 Driver，可能跨节点，也可能都发生在同一节点；图中“数据侧 / 协调侧”是职责，单节点实验不能当作跨机器网络传输或性能验证。

27.4 Page 是列式批次，Driver 是单链执行

Page 保存 Block[] 与 positionCount，每个 Block 是一列，各列有相同的行位置数；一个位置可以空、单值或多值。抽取 views 后，Page 仍可能保留文档位置等实现用列，不能说“Page 里只剩 views”。列式布局让算子按批读取相关列，但不保证所有类型都用同一种压缩、连续内存或 SIMD 路径，也不构成速度承诺。Page的列式与行位置契约。

Driver.runSingleLoopIteration 检查上游是否阻塞、下游是否 needsInput，再调用上游 getOutput，把非空 Page 交给下游 addInput；空页可直接释放。一个 Driver 在某一时刻单线程推进一条算子链，多个 Driver 可以并行调度，不能据此说整个 ES|QL 只有一个线程。未下推的 FilterOperator 对布尔测试的 null 或非单值结果不选择该行，这是算子的布尔结果语义，不代表一切多值字段都不可全文匹配。Driver.runSingleLoopIteration。

Operator.TARGET_PAGE_SIZE 是 256 KiB 的目标字节数。普通数据源规划会结合估算行宽计算目标行数，并保留最小行数；显式 page_size 或时序源又有分支。中间聚合页、可变宽度列和批次元数据都影响实际大小。因此“每页固定 256KB”与“256KB 是内存上限”都不成立。pageSize估算及分支。

27.5 没有 hits 包装，不等于没有全文评分

本课默认 JSON 回 columns 和 values，主查询的一行是 [[200.0]]。它没有 _search 的 hits.hits 包装；本课又没有请求评分，因此不出现 _score 列。ES 9.4.0 的 ES|QL 已支持 MATCH 等全文函数与 METADATA _score。D1 在显式 text/standard 的 description 上查 fox，返回 a、b 两行和正分数；可用 SORT _score DESC 排序。本轮响应的 _score 列类型为 double，MetadataAttribute 的固定源码也注册 DataType.DOUBLE；文档表中的 float 描述不能替代响应契约。_score 类型注册。官方固定版本也允许 METADATA _source，不能把列式中间表示推广成“ES|QL 永远不读或返回 _source”。_score与_source元数据字段。

索引型 FROM 仍依赖搜索可见性。D 组在显式 refresh_interval=-1 下写第六篇300、refresh=false；realtime GET立即可读，FROM仍数到五篇。显式刷新后，主查询变225；删除六号文档并 refresh=true 后恢复200。只有无外部刷新的前提成立，这个对照才有效；refresh 是更新搜索视图，不等同持久化提交。

实验：四组对照与完整重做

使用专用单节点 ES9.4.0 / Lucene10.4.0，端点 localhost:9200，默认匿名；启用安全时选择相应认证并具备本课资源操作权限。两个本课索引起步必须 HEAD404。索引显式一主零副、auto_expand=false、strict mapping、refresh_interval=-1；只在本索引内写入、刷新、删除，不修改集群设置。A–D按顺序执行，卡片的预测、请求与对照分别展示；预期错误也是实验结果。

本轮验证记录：真实API的初次、清理后重做及补充观察见 本章验收记录；页面数字基于这套固定数据，环境与资源条件变化须重新对照。控制台支持端点、认证别名与请求深链。
  1. 前置：读版本，确认两个索引不存在；已有资源先确认属于本课再清理。
  2. A：建主索引 → green → 读配置 → bulk显式refresh → count5 → 管道变体、profile、LIMIT与类型拒绝。
  3. B：DSL avg / hits / size1 → 两种错误路径或方法；本组不创建异步结果。
  4. C：另建值索引 → green → 四篇固定ID并refresh → count4 → 有效值计数与空聚合。
  5. D：MATCH评分 → 写第六篇不刷新 → GET / FROM 对照 → refresh → 均值225 → 删六号并刷新 → 均值恢复200。
  6. 清理：两索引分别点名DELETE，再HEAD404。完整重做回到前置；D中断时先D7恢复，再从D2继续。

思考题

1. 四条管道的均值为何是200、175、150、225？

>100筛三行得到600/3=200；>=100筛四行得到700/4=175；无WHERE是750/5=150；先筛再按views降序LIMIT2，输入只剩250/200，平均225。STATS后LIMIT1不改变三行输入。优化器可以改执行地点，不能随意改变这些集合。

2. COUNT(*)=4，为什么AVG却除以3？空输入为什么不是0？

C组四篇中只有10、20、40三个有效值，COUNT(field)计入多值、忽略null与缺失，AVG=70/3。空输入没有有效均值，无BY仍输出一行null，COUNT(*)为0；中间态的seen/null信息保证这个语义。

3. profile没有FilterOperator且出现三个Driver，图错了吗？

可下推条件可进入Lucene query，无独立过滤算子不意味着WHERE丢失；图注明确省略辅助中转Driver。真实算子链依具体计划决定，需结合固定源码和边界结果，不能从源算子名推断内部range。

4. 两个局部均值150与225，为什么不直接平均？

两组样本数为1与2，直接平均是187.5；应先合并Sum150+450与Count1+2，得到600/3=200。有效字段值数才是本例权重，部分状态还含有效性信息。

5. 没有hits，能否推断不能评分？GET看到第六篇，FROM为何仍五篇？

不能。ES9.4支持MATCH与METADATA _score，结果仍以表返回。GET默认realtime；索引型FROM使用搜索视图。D组关闭自动refresh并排除外部刷新后，未刷新写入可由GET读到，FROM等显式刷新才可见。

陷阱

把命令顺序当成固定物理链：WHERE可下推，AVG可改写，辅助Driver可以增加；顺序约束结果语义，具体计划允许等价变化。
把AVG分母写成文档数：仅非空单值时才相等；本课四篇有三个有效值，空聚合AVG=null。
把256KiB当成Page上限：这是按估算行宽计算批次的目标，并非固定字节数；内存仍受实际列、状态与资源管理影响。
宣称ES|QL没有_score或_source：本课STATS没有请求这些列，9.4的METADATA却支持它们；全文函数也能贡献评分。
把size与前置LIMIT混为一谈：DSL size只控制命中窗口；显式STATS前LIMIT改变聚合输入。默认输出截断又是另一个条件。
重复写入与自动刷新破坏前提：固定ID重复bulk不会增篇但会updated；本课自动refresh关闭，D实验仍须排除外部刷新，末尾删除并刷新后才能恢复A组。
