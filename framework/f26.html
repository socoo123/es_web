FRAMEWORK 26 · 最低价来自哪个集合

酒店列表的“最低价”
究竟是哪一种价格？

前置：F23独立报价、F24匹配范围、F25逐晚核对 · 约85分钟 · 3案例 / 24教学HTTP · 2静态D2 / 0机制播放器

F25已经能逐晚判断一条报价，却会把同一家酒店的多个房型列成多条。游客想看“一家酒店一张卡，含早可退的两晚最低总价”；运营若直接去重并贴上最低起价，卡片仍可能误导。本课学习ES怎样折叠报价、展开同酒店的匹配报价，以及候选范围怎样决定“最低价”能承诺到哪里。

学完能用输出证明什么

  • 用10条报价、6家候选酒店说明collapse、hits.total、cardinality与实际展示条数的区别。
  • 核对h01的代表报价、inner_hits的3条总数和不同size，指出不含早的o04为何不应进入最低价。
  • 以三种候选范围复现两晚总价，找出酒店内与酒店外遗漏，用完整集合证明本快照的4家合格酒店次序。

1. “最低”是一个集合上的比较，不是字段名称

Elasticsearch负责按文档条件检索、分组展示和排序。本课仍用一条offer文档表示“酒店×房型×报价计划×币种”的搜索摘要；Java用固定逐晚表验证连住资格。数据库或供价系统的实时库存、订单事务不在这张搜索卡片中完成。

先问三个不同的问题：酒店所有报价里最便宜的单晚是多少？符合含早可退条件的报价里，单晚起价最低是多少？符合这些条件且本次每晚有房的报价里，两晚总价最低是多少？三者比较的集合和金额都不同。h01的o04每晚50元但不含早；o01起价100元，两晚却1000元；o02起价400元，两晚800元。如果卡片写“含早可退，两晚100元起”，读者得到的意思与证据不符。

本课的“起价”明确指同一报价在固定逐晚表中的最低有效单晚价，单位是CNY分/每间/每晚，不保证恰好是入住首晚。入住总价则是本次[入住,离店)每晚房费之和。本次只订一间，两名成人，不设总预算过滤；不含税费，也不做跨币种换算。字段min_price_minor只支持前一种金额，不能乘以晚数冒充后一种。

2. 先区分候选报价、候选酒店和合格酒店

固定逐晚表含16条报价、9家酒店，快照为f26-20261027-v1。入住2026-11-01，离店03，杭州当地日期Asia/Shanghai；只核对1日、2日。默认双床、含早、flexible、每间容量2成人、酒店open、报价active、CNY。每条offer有独立room_id与rate_plan_id，不把不同房型的晚拼起来。

ES先检查静态条件、日期两端、最大库存和有效起价，得到10条候选报价，去重为6家候选酒店。摘要仍会放进缺晚、售罄或最短入住不符的报价。逐晚核对后才有7条合格报价，属于4家合格酒店。这三个计数应各有名称，不能把“候选6家”直接显示成“6家可订”。min_stay_arrival继续沿用F25的教学规则，只读取入住日的最短晚数。

3. f26-c01：先数报价，再折成酒店

本课独立使用127.0.0.1:19226、tut-f26-offers和es-framework-f26容器组，ES9.4.0/Lucene10.4.0，单节点、一主零副本、无插件、无认证，仅绑定回环地址。索引dynamic=strict，整数禁coerce，refresh_interval=-1；写入后显式refresh，避免自动刷新时机改变观察结果。不要把本课清理命令改成通配符。

4. collapse为同一酒店挑一个代表，不聚合总价

普通搜索按起价升序，10个ID是o01、o05、o09、o10、o02、o03、o06、o07、o08、o16。h01占三条，h02占两条。将hotel_id作为折叠键，ES在每个键对应的匹配文档中保留外层sort最靠前的一条，再返回这些代表。这个能力叫字段折叠collapse。它改变结果展示单位，没有把ES文档改写成酒店文档。

下面是完整请求。它先限定含早等条件，再按min_price_minor、hotel_id、offer_id升序，collapse按酒店去重；size=10至多取10家酒店。inner_hits的offers另按同样规则取每家前2条。聚合candidate_hotels对整个query命中的集合计算基数估计，不是只统计当前返回的酒店卡片。

5. f26-c02：inner_hits展开的是什么，漏了什么

本课的inner_hits不是F24那种nested子文档：这里每条报价都是根文档，折叠按hotel_id把它们分组。展开时，ES保留原查询条件，再加当前酒店条件，所以h01的组内总数为3，只有o01/o02/o03；更便宜却不含早的o04不在里面。它取回的是本query的同酒店匹配报价，不是酒店所有房型，更不是Java逐晚核对后的合格集合。

运行下面对照，逐次查看inner_hits.offers.hits.total与hits数组。size为1、2、10时，h01分别返回[o01]、[o01,o02]、[o01,o02,o03]，total均为3。把组内排序改为起价降序且size=1，返回o03；外层h01代表仍是o01，酒店外层次序不变。两层sort和size各自负责自己的结果，不会互相替代。

6. f26-c03：酒店内完整，也不代表酒店间完整

Top K就是只取某种次序下的前K个对象，必须说清对象是报价还是酒店、用什么价格排序。本课固定K=2，比较三种真实Java输入。top-offers按起价取前2条报价；top-hotels先折成前2家酒店，再完整展开各自的匹配报价；all不折叠，取回全部候选，核对后才按酒店选最低总价。三者都执行同一逐晚规则，差别在于谁有机会被检查。

mode / 已核对范围实际酒店与两晚最低值（CNY分）能够证明什么
top-offers：2条 / 2家h01/o01=100000；h02/o05=120000仅已查报价最低值，酒店内仍漏
top-hotels：5条 / 2家h01/o02=80000；h02/o06=100000这两家酒店内精确，酒店范围仍漏
all：10条 / 6家候选h04/o09=60000；h05/o10=60000；h01/o02=80000；h02/o06=100000固定条件与快照内完整核对；7条合格 / 4家酒店

h04/h05单晚起价30000分，排在起价10000和20000分的h01/h02之后，所以没进前2家；两晚总价却都更低。即使对前2家内部的报价全部核对，再重新排序，也不能让没被选中的酒店重新出现。候选内重排只能改变候选内次序，不能保证全局精确总价排序。本例K=2失败不等于存在一个总能保证正确的固定K；要给出保证，需要完整集合或有证明的界限与检索策略。

完整核对中o07缺晚、o08售罄、o16最短入住失败，因此h03/h09整家没有合格报价。h04与h05总价相同，以hotel_id升序打破同价；酒店内部同总价则以offer_id升序选代表。这些键让本次次序可重现，不把单次搜索的稳定性等同于并发改价下的稳定视图。

7. Java把搜索范围、逐晚资格和酒店投影分开表达

应用沿用Boot4.0.8、Temurin JDK25.0.4.1+1、官方Java API Client与Rest5 Client9.4.8、Wrapper3.3.4/Maven3.9.11。ES镜像自己的JVM是26.0.1+8；两个JDK不混写。客户端复用和关闭由现有配置管理。本课接口只接受三种mode，固定日期与人数，完整输入DTO和Controller见折叠区。

request方法构建上面的同一query；all将size设为100，top-offers设为2，top-hotels设为2并附加至多10条inner_hits。这里的100和10是教学保护上限，绝不表示ES或酒店本身只有这些数量。完整Java DSL已与三个固定REST JSON逐字段相等核对，再将Java生成的请求重放到真实ES，比对全部ID、_source、sort、total和inner_hits。

    public SearchRequest request(CollapseInput input) {
        var b=new BoolQuery.Builder();
        for (String[] p:new String[][]{{"city_code","HZ"},{"hotel_status","open"},{"offer_status","active"},
                {"bed_type","twin"},{"meal","breakfast"},{"cancellation","flexible"},{"currency","CNY"}})
            b.filter(q->q.term(t->t.field(p[0]).value(p[1])));
        b.filter(q->q.range(r->r.number(n->n.field("capacity").gte(2.0))));
        b.filter(q->q.range(r->r.date(d->d.field("window_start").lte("2026-11-01"))));
        b.filter(q->q.range(r->r.date(d->d.field("window_end_exclusive").gte("2026-11-03"))));
        b.filter(q->q.range(r->r.number(n->n.field("max_available_rooms").gte(1.0))));
        b.filter(q->q.exists(e->e.field("min_price_minor")));
        List<SortOptions> sort=new ArrayList<>();
        for (String field:List.of("min_price_minor","hotel_id","offer_id"))
            sort.add(SortOptions.of(s->s.field(f->f.field(field).order(SortOrder.Asc))));
        var r=new SearchRequest.Builder().index("tut-f26-offers").size(input.mode().equals("all")?100:2)
                .trackTotalHits(t->t.enabled(true)).query(q->q.bool(b.build())).sort(sort)
                .aggregations("candidate_hotels",a->a.cardinality(c->c.field("hotel_id").precisionThreshold(100)));
        if (input.mode().equals("top-hotels"))
            r.collapse(c->c.field("hotel_id").innerHits(i->i.name("offers").size(10).sort(sort)));
        return r.build();
    }

每条返回报价须能在同一快照逐晚表中找到，而且摘要_source须完整相等；资料缺失、身份变化、旧快照不会被当作“没房”吞掉。业务拒绝才用MISSING_NIGHT、SOLD_OUT、MIN_STAY等原因。日期左闭右开，只核对入住两个住宿晚；sum累加每晚整数分，不用起价乘2。以下是完整身份检查与逐晚判断：

    private JsonNode source(String id, JsonNode s) {
        require(s!=null && s.hasNonNull("offer_id") && id.equals(s.get("offer_id").asString()));
        JsonNode offer=table.get(id);
        require(offer!=null && offer.get("summary").equals(s)); // fail closed on missing/stale/altered identity or summary
        return s;
    }
    private Decision decide(JsonNode s) {
        String id=s.get("offer_id").asString(); JsonNode nights=table.get(id).get("nights");
        Map<String,JsonNode> byDate=new HashMap<>();
        for (JsonNode n:nights) byDate.put(n.get("date").asString(),n);
        String reason="ACCEPTED"; long sum=0;
        JsonNode arrival=byDate.get("2026-11-01");
        if (arrival!=null && arrival.get("min_stay_arrival").asInt()>2) reason="MIN_STAY";
        else for (LocalDate d=LocalDate.of(2026,11,1);d.isBefore(LocalDate.of(2026,11,3));d=d.plusDays(1)) {
            JsonNode n=byDate.get(d.toString());
            if (n==null) reason="MISSING_NIGHT";
            else if (n.get("available_rooms").asInt()<1) reason="SOLD_OUT";
            else if (!n.hasNonNull("price_minor")) reason="MISSING_PRICE";
            if (!reason.equals("ACCEPTED")) break;
            sum=Math.addExact(sum,n.get("price_minor").asLong());
        }
        return new Decision(id,s.get("hotel_id").asString(),s.get("hotel_name").asString(),reason,
                reason.equals("ACCEPTED")?sum:null,nights);
    }

all必须满足total.relation=eq且total.value等于已返回条数，否则拒绝输出完整最低价。top-hotels还要求每个组的精确total等于返回条数；超过10条时返回502，不能拿截断组声称该酒店最低。top-offers本就明确有限，只称“已查报价最低”。查询超时、分片失败或字段不全同样拒绝；这些防护不会自动解决生产环境的并发快照一致性。

投影先过滤逐晚合格报价，再按hotel_id归组，组内按总价、offer_id选最低，最后按最低总价、hotel_id排酒店。空组不产生酒店卡。response保留candidateOfferTotal、cardinality估计、实际检查数、合格报价数、展示酒店数、范围说明，以及完整请求和原始响应；不会用一个total掩盖几种口径。

    public Result inspect(CollapseInput input) throws IOException {

        require(!response.timedOut() && response.shards().failed().longValue()==0 && response.hits().total()!=null
                && response.hits().total().relation().jsonValue().equals("eq"));
        boolean all=input.mode().equals("all"); long total=response.hits().total().value();
        if (all) require(total==response.hits().hits().size()); // fixed full collection limited to 100, never silently truncate
        JsonNode raw=tree(response); Map<String,JsonNode> selected=new LinkedHashMap<>(); Set<String> groups=new HashSet<>();
        for (JsonNode hit:raw.path("hits").path("hits")) {
            JsonNode root=source(hit.path("_id").asString(),hit.get("_source"));
            if (input.mode().equals("top-hotels")) {
                String hotel=root.get("hotel_id").asString(); require(groups.add(hotel));
                JsonNode inner=hit.path("inner_hits").path("offers").path("hits");
                require(inner.path("total").path("relation").asString().equals("eq")
                        && inner.path("total").path("value").asLong()==inner.path("hits").size());
                boolean foundRoot=false;
                for (JsonNode h:inner.path("hits")) {
                    String id=h.path("_id").asString(); JsonNode s=source(id,h.get("_source"));
                    require(s.get("hotel_id").asString().equals(hotel) && selected.putIfAbsent(id,s)==null);
                    foundRoot |= id.equals(root.get("offer_id").asString());
                }
                require(foundRoot); // group representative must also occur in the complete inner collection
            } else require(selected.putIfAbsent(hit.path("_id").asString(),root)==null);
        }
        List<Decision> decisions=selected.values().stream().map(this::decide).toList();
        Map<String,List<Decision>> accepted=new TreeMap<>();
        for (Decision d:decisions) if (d.reason().equals("ACCEPTED"))
            accepted.computeIfAbsent(d.hotelId(),k->new ArrayList<>()).add(d);
        List<Hotel> hotels=new ArrayList<>();
        for (var entry:accepted.entrySet()) {
            var offers=entry.getValue(); offers.sort(Comparator.comparingLong((Decision d)->d.totalMinor()).thenComparing(Decision::offerId));
            Decision best=offers.getFirst();
            hotels.add(new Hotel(best.hotelId(),best.hotelName(),best.offerId(),best.totalMinor(),offers.stream().map(Decision::offerId).toList()));
        }
        hotels.sort(Comparator.comparingLong(Hotel::minimumTotalMinor).thenComparing(Hotel::hotelId));
        String boundary=switch(input.mode()) {
            case "all" -> "本固定快照全部ES候选逐晚核对；合格酒店最低总价全量排序，限100条且完整性检查通过。";
            case "top-hotels" -> "仅前2家候选酒店；每家至多10条并检查完整，能得出这些酒店的最低总价，不能保证全局最低或全局次序。";
            default -> "仅前2条报价；酒店内和酒店间都可能遗漏，只是已检查报价中的最低总价。";
        };
        require(response.aggregations()!=null && response.aggregations().containsKey("candidate_hotels"));
        return new Result(input,SNAPSHOT,boundary,all,total,response.aggregations().get("candidate_hotels").cardinality().value(),
                decisions.size(),(int)decisions.stream().map(Decision::hotelId).distinct().count(),
                (int)decisions.stream().filter(d->d.reason().equals("ACCEPTED")).count(),hotels.size(),
                List.copyOf(hotels),decisions,tree(request),raw);
    }

官方依据与本课适用条件

官方collapse说明支持代表文档、计数/聚合范围与分页约束；cardinality说明明确估计性质。本课锚定v9.4.0并实际运行；固定tag源码CollapseBuilder.build核对字段与doc_values要求，ExpandSearchPhase.doRun / buildExpandSearchSourceBuilder核对原query加酒店条件、独立size/sort与追加搜索。来源和哈希与真实请求分开记录。最低总价规则来自本课固定业务契约，不声称ES替业务定义“合格”。

10. 找到最低总价之后，酒店一定按它排吗

本课为了验证价格范围，完整结果按两晚最低总价升序。但游客也可能先挑离西湖近、评价可靠的酒店，再在该酒店里选含早可退的便宜房。F27才讨论酒店相关性/品质/距离与房型总价/偏好的两层排序。本课止于去重、计数和价格范围，不提前把整套策略藏进一个评分公式。

能力检查：先判断，再展开

1. 一次响应显示2家，hits.total=10，cardinality=6，分别在数什么？

2是当前返回的酒店卡片数，10是query匹配的报价文档数，6是该query下hotel_id的基数估计。它们都不是逐晚合格酒店总数；本课完整核对后才有4家。

2. h01“全酒店50元起”能写成“含早50元起”吗？

不能。o04不含早，被完整条件排除。完整query下最低单晚起价是o01的10000分，仍不是入住两晚最低总价80000分。

3. h01的inner total=3、size=1，只返回o01，可以称酒店最低总价1000元吗？

不能。只检查了起价最便宜的一条；o02两晚800元尚未检查。应明确“已查报价中的最低值”，或完整取回该酒店全部匹配报价再核对。

4. 前2家酒店内部都完整核对了，为什么仍排不出全局最便宜酒店？

因为h04/h05没进入候选酒店范围，内部核对再精确也不会生成它们。两家各60000分，比h01的80000、h02的100000低。

5. 把inner sort反过来，外层h01代表会变成o03吗？

不会。本课反向组内排序size=1取o03，但外层仍按起价升序代表o01，两层排序分别作用于自己的集合。

6. all取100条，如果total=110，能输出“全量最低”吗？

不能，返回集合不完整，Java返回502。实际注入101条附加报价后触发该防护；删除点名测试ID后恢复。相同道理，组内total超过10也不能声称完整酒店最低。

7. 独立推演：给范围外新增h10，两晚各25000分，完整结果应怎样变化？

若其身份/政策/币种/人数/逐晚库存均满足且固定表与摘要同版本，完整核对后h10/50000分应排在h04/h05之前；仅前2家起价范围仍可能漏掉它。这是推演题，未新增到正式ES固定样本，也不宣称已经执行。

实际陷阱

给最低价省略限定词。酒店全部报价、ES条件匹配报价、本次逐晚合格报价是不同集合；币种、日期和税费口径也必须一致。

把collapse当酒店计数或全量抓取。它选代表，total仍数报价；外层与组内size都会截断，cardinality也不因折叠变成精确计数。

精确复核被误读成全局精确排序。逐晚规则正确只证明被检查的报价；范围外更低价仍可改变酒店最低值和次序。
