本课目标

  1. 固定查询条件，复现相关性、价格、距离三种完整 ID 次序，证明候选集合不变而排列改变。
  2. 解释排序值的单位、缺价/缺坐标与唯一第二键，区分 sort、过滤、评分与展示值。
  3. 逐项核对 REST、Java DTO 和真实观察页，验证 track_scores 开关、预算/城市硬约束、正常空集及错误恢复。

1. “排第一”只在一把尺子下成立

搜索分成两个问题：哪些资料符合条件，符合的资料先看谁。Elasticsearch 是搜索与分析引擎，query 决定匹配范围，sort 决定命中次序。本课没有让 ES 决定售卖资格、真实库存或景点星级。Java 把允许的排序方式翻译为固定字段，展示壳把单位与缺失状态显示清楚，业务含义仍由我们约定。

先想两个西湖：杭州西湖和福州西湖都免费；若游客在杭州，免费不能区分远近，距离却可以。同样，“西湖预算线”的名称匹配不错，但200元不该在价格升序里压过免费景点。三种模式分别回答“文本匹配得怎样”“票价多低”“离指定圆心多近”，不能把分数、分和公里直接比较或相加。

没有显式 sort 时，普通搜索默认按 _score 降序；F07–F09 为便于逐项核对，已经显式按 ID 排序，因此它们的界面顺序不是 ES 默认相关性。F10 的相关性模式显式写 _score desc，再加 ID 升序处理同分。本课学习排序契约，不推导 BM25，也不把当前样本的高分当推荐质量评估，评分解释留到 F18。

5. sort是一个有顺序的元组

价格模式杭州西湖返回 [0,"a-hz-xihu"]，远处展馆返回 [1000,"a-hz-far"]；先比较0与1000，只有相同才看ID。同为1000分的四份按 far、guide、missing-location、plain 排列；它们的评分或距离不同也不会插队。距离模式前三份本次完整首值均0.0，guide、plain、xihu便由第二键决定。

稳定第二键要求在当前查询覆盖范围内唯一、存在、值稳定。keyword类型本身不强制唯一，样本导入和业务约束共同保证。这里对一个固定数据视图给出确定的全序；索引有更新、评分统计改变或翻页请求时视图变化，唯一ID也不能冻结前后两次看到的集合。F11再处理分页与固定搜索视图，本课不交付游标或PIT。

8. f10-c03：同一排序契约交给Java

新增POST /api/attractions/sort-search，请求模式只能为relevance/price/distance，城市为ALL/HZ/FZ/SH，预算为0–100000000整数分，坐标必须有限且在纬度±90、经度±180内，评分开关必填。服务端固定本课索引，不接受客户端任意字段名或排序DSL；即使价格模式当前不用圆心，也保持同一完整输入契约。

package dev.esweb.travel;

import jakarta.validation.constraints.*;

public record SortInput(
        @NotBlank @Size(max = 60) String q,
        @NotNull @Pattern(regexp = "ALL|HZ|FZ|SH") String cityCode,
        @NotNull @Min(0) @Max(100000000) Integer maxPriceFen,
        @NotNull @Pattern(regexp = "relevance|price|distance") String sortMode,
        @NotNull @DecimalMin("-90") @DecimalMax("90") Double latitude,
        @NotNull @DecimalMin("-180") @DecimalMax("180") Double longitude,
        @NotNull Boolean trackScores) {
}

关键实现如下：先构建同一bool，再按模式添加首键，最后始终追加ID。查询不包含半径，不能让“距离模式”暗中变成“附近过滤”。DTO直接保留ES返回次序和完整排序值，只有距离模式且有坐标时才从首排序值读取distanceKm，不在Java重算或对卡片另排。

package dev.esweb.travel;

import co.elastic.clients.elasticsearch.ElasticsearchClient;
import co.elastic.clients.elasticsearch._types.*;
import co.elastic.clients.elasticsearch._types.query_dsl.*;
import co.elastic.clients.elasticsearch.core.SearchRequest;
import co.elastic.clients.json.JsonpUtils;
import java.io.IOException;
import java.util.List;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Service;
import tools.jackson.databind.json.JsonMapper;

@Service
public class SortSearchService {
    private final ElasticsearchClient client;
    private final String index;
    private final JsonMapper json;

    public SortSearchService(ElasticsearchClient client,
            @Value("${travel.f10-index:tut-f10-attractions}") String index, JsonMapper json) {
        this.client = client; this.index = index; this.json = json;
    }

    public SearchRequest request(SortInput input) {
        var bool = new BoolQuery.Builder()
                .must(m -> m.multiMatch(t -> t.query(input.q()).fields("name^3", "aliases^2", "description")
                        .type(TextQueryType.BestFields).operator(Operator.And).tieBreaker(0.0)))
                .filter(f -> f.term(t -> t.field("currency").value("CNY")))
                .filter(f -> f.range(r -> r.number(n -> n.field("ticket_price_fen")
                        .gte(0.0).lte(input.maxPriceFen().doubleValue()))))
                .filter(f -> f.term(t -> t.field("status").value("open")));
        if (!input.cityCode().equals("ALL")) {
            bool.filter(f -> f.term(t -> t.field("city_code").value(input.cityCode())));
        }
        var search = new SearchRequest.Builder().index(index).size(20)
                .trackTotalHits(t -> t.enabled(true)).trackScores(input.trackScores())
                .source(src -> src.filter(f -> f.includes(List.of("attraction_id", "name", "city_code",
                        "ticket_price_fen", "currency", "status", "location"))))
                .query(q -> q.bool(bool.build()));
        switch (input.sortMode()) {
            case "relevance" -> search.sort(s -> s.score(f -> f.order(SortOrder.Desc)));
            case "price" -> search.sort(s -> s.field(f -> f.field("ticket_price_fen")
                    .order(SortOrder.Asc).missing(FieldValue.of("_last"))));
            case "distance" -> search.sort(s -> s.geoDistance(g -> g.field("location")
                    .location(l -> l.latlon(p -> p.lat(input.latitude()).lon(input.longitude())))
                    .order(SortOrder.Asc).unit(DistanceUnit.Kilometers)
                    .distanceType(GeoDistanceType.Arc).mode(SortMode.Min).ignoreUnmapped(false)));
            default -> throw new IllegalArgumentException("Unsupported sort mode");
        }
        return search.sort(s -> s.field(f -> f.field("attraction_id").order(SortOrder.Asc))).build();
    }

    private Object sortValue(FieldValue value) {
        return switch (value._kind()) {
            case Double -> value.doubleValue();
            case Long -> value.longValue();
            case String -> value.stringValue();
            case Null -> null;
            default -> throw new AttractionSearchService.IncompleteSearchException();
        };
    }

    public SortResult search(SortInput input) throws IOException {
        var request = request(input);
        var response = client.search(request, SortAttraction.class);
        if (response.timedOut() || response.shards().failed().longValue() != 0 || response.hits().total() == null) {
            throw new AttractionSearchService.IncompleteSearchException();
        }
        var items = response.hits().hits().stream().map(hit -> {
            var src = hit.source();
            if (src == null || !hit.id().equals(src.attractionId()) || src.name() == null
                    || src.ticketPriceFen() == null || hit.sort().size() != 2) {
                throw new AttractionSearchService.IncompleteSearchException();
            }
            var values = hit.sort().stream().map(this::sortValue).toList();
            Double distanceKm = null;
            if (input.sortMode().equals("distance") && src.location() != null) {
                if (!(values.getFirst() instanceof Number number) || !Double.isFinite(number.doubleValue())) {
                    throw new AttractionSearchService.IncompleteSearchException();
                }
                distanceKm = number.doubleValue();
            }
            return new SortResult.Card(hit.id(), src.name(), src.cityCode(), src.ticketPriceFen(),
                    src.currency(), src.status(), hit.score(), values, src.location() != null, distanceKm);
        }).toList();
        String dsl = JsonpUtils.toJsonString(request, client._jsonpMapper());
        return new SortResult(response.hits().total().value(), response.hits().total().relation().jsonValue(),
                response.took(), input, json.readTree(dsl), items);
    }
}

版本依据与适用范围

官方排序文档提供语义入口；在线页可能变化，版本以本轮ES9.4.0实测与固定tag源码为锚。目标文件与远端逐字节比较记录在来源收据，不是通过当前在线默认值猜测本课行为。

  • SortBuilder.buildSort：按列表顺序构造排序字段。
  • FieldSortBuilder.missing/build：字段缺值配置；不修改_source。
  • GeoDistanceSortBuilder.build/comparatorSource：地理距离与缺坐标正无穷。
  • QueryPhaseCollectorManager：分数/字段收集路径；结合真实track_scores对照。

这不是多节点稳定分页或性能实验；唯一第二键不冻结数据视图，固定次序也不证明评分质量、实际票价与交通距离。

能力检查：解释后再打开

1. 两种模式都返回9份，为什么首位能从上海展馆变成福州西湖？

候选条件相同，sort首键不同：相关性比较_score，价格比较整数分。免费福州西湖因与杭州西湖同价，再按完整ID字典序在前。不是价格改变了召回。

2. 同为1000分，far评分更低也更远，为什么还在guide前？

价格请求只写票价asc、ID asc。票价相同直接比较ID；track_scores=true只增加评分返回，不把评分加入排序。

3. 缺价设置missing=0，文档变成免费了吗？

没有，只影响排序替代值，_source未改。主查询range仍排除缺价。独立四文档反例去掉预算后，两份缺价与真实0分同首值，ID使缺价在前。

4. 距离末尾的Infinity能显示为0km吗？加3km半径会怎样？

不能，待定位不是零距离；保存原始sort值，展示待定位。加入3km过滤后，缺坐标、远处展馆、上海和福州都不满足，仅guide/plain/xihu/boundary/tea五份，但这已经改变查询集合。

5. ID唯一后，明天翻页还一定没有重漏吗？

不能这样承诺。唯一第二键让一个固定视图内的同分/同价/同距可确定，前后请求有数据或评分统计变化仍会变。下一课用完整sort、游标和PIT讨论视图一致性。

6. 独立操作：切价格、开评分、改80元、输入火星、删索引，分别核对什么？

切价格九份；开评分仍同ID同sort、_score从null变数字；80元七份去掉boundary和exhibit；火星200空集；缺索引502清空旧卡片，重新01导入恢复。不要拿空结果当服务故障，也不要把HTTP200当所有分片完整。

容易误读的四件事

把价格、距离、评分当同一种优先级。三把尺子回答不同问题。先固定集合与单位，再看明确的sort字段和顺序。
以为缺价是0、缺坐标就在圆心。字段缺失、显式null与有效0分不同；geo缺值按正无穷，不能伪造0km。
开了track_scores便以为相关性参与同价排序。是否比较评分由sort数组决定，开关不是隐式排序键。
把ID第二键当跨请求不变的保证。先保证字段唯一、非空且稳定；它只消除当前视图内主键相同的歧义，分页视图仍需下一课处理。
