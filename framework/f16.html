怎样找到同一景点？

学完能证明什么

  • 用同一资料集解释显式别名与查询同义词补回了谁、又误入了谁，城市条件怎样独立生效。
  • 读取position与positionLength，画出单词/多词的替代路径，预测默认AND、放宽分支与完整短语的不同命中。
  • 验证繁简、分析链顺序、别名更新与搜索同义词重载，说明何时需要重新写入资料，并让REST、Java与卡片一致。

1. 切对了词，仍可能找不到同一个地方

F15解决了新品牌和地名怎样进入词典。“紫禁城”和“故宫”却是另一类问题：即使两个名字都切得合理，它们也没有相同词项。ES负责按照索引表达检索，不会仅凭历史知识自动知道游客指向哪里。资料维护方需要提供别名关系，或者为搜索规则声明哪些表达可以互相替代。

这仍是旅游网站的搜索层：浏览器提交关键词与城市，Java选择查询，ES返回候选。景点身份、别名审核与相关性判断来自业务资料。新增同义词不是给资料发“官方景点”认证；在北京能搜到“故宫主题餐厅”，不代表它符合游客的宫殿游览意图。

2. 先区分三种改法，决定关系放在哪里

显式别名是某份文档的另一个名字，例如只在bj-palace的aliases数组写“紫禁城”。检索原名与别名，能把这个叫法连接到指定资料。这里的aliases是普通text字段，不是F32的索引alias，也不是mapping中的alias字段类型。维护成本是给具体资料补数据；一处别名不会自动分配给所有含“故宫”的商户。

同义词在本课是查询分析中的替代规则。“紫禁城, 故宫”表示等价展开；显式设置expand=true保留双方路径。“旧称 => 新称”则只从左侧改写到右侧，不能据此假定反向也成立。我们把synonym_graph放在搜索链，名称写入链不展开同义词。它能复用语言规则，但规则作用于词项，范围比单份实体别名大。

繁简归一把“故宮”转换为“故宫”这一种文字形式。本课用ICU的Traditional-Simplified，索引与查询都归到简体；_source保留原文。它不把“紫禁城”变成“故宫”，也不解决一词多义、地区用语或实体身份。三种改法可以配合，却不能用其中一种的成功证明另外两种正确。

6. f16-c02：多词同义词是一条替代路径

palace是一个token，forbidden city是两个。如果只画成一堆同位置词，后面的museum应该接在哪里就不清楚了。token graph用位置作节点，每个token是从position到position+positionLength的边。synonym_graph记录多位置跨度，让查询能沿不同完整路径理解同义表达。官方词图说明指出索引不保留这种多位置图语义，因此本课在查询阶段使用它。

bash labs/f16/02-graph.sh
{
  "analyzer": "travel_search",
  "text": "PALACE museum",
  "explain": true
}

实际最后一层有下列四条边。offset仍指向原输入，不是新词字符串中的字符位置；forbidden与city都来自PALACE的[0,6)，不要求输出字数等于区间长度。explain=true还保留各层完整属性，不能只看最后一列词面。

7. 为什么小写与繁简必须先到达同义词

本课正确链是standard → lowercase → t2s → travel_syn。之前的filter不仅处理用户输入，也参与解析同义词规则，所以查询与规则能在同一文字形式下比较。顺序反例travel_late把travel_syn放在最前，后面的转换无法让已经错过的规则重新匹配。官方顺序与规则说明和v9.4.0固定源码共同核对了这点。

实际PALACE museum在正确链生成四条边，在late链只有palace、museum两条边，搜索为0。故宮在正确链先变成故宫，再展开到紫禁城；late只在扩展结束后变简体，因此只得bj-palace、bj-theme、bj-traditional，漏掉bj-wall。这两个反例都不是“字符最后看起来一样就能补救”。

stop放在同义词前还可能把规则的一侧全部删掉。02用完整临时分析请求删除palace，再解析palace => forbidden city；lenient=false实际报400与completely eliminated。它没有改动本课已配置分析器，随后正确查询仍恢复2份。不能用忽略错误掩盖规则没有生效；新规则需要验证分析与搜索两层。

查询“故宮”用不转繁简的travel_plain时为0；别名模式用travel_base，得到bj-palace、bj-theme、bj-traditional、bj-wall。最后一份来自自己的“故宫城墙”别名，其余来自名称。成功的是统一了查询与索引的文字形式，并未证明所有候选相关。ICU转换发生在tokenizer之后；本课standard逐字样本验证了这些字，不把结果推广为所有中文分词器、上下文和地区用词的完整转换保证。ICU transform官方入口解释转换ID与方向。

10. Java沿用同一查询语义，词图不要丢跨度

沿用Boot4.0.8、Temurin25.0.4.1+1、官方Java及Rest5 Client9.4.8、Wrapper3.3.4/Maven3.9.11；ES容器自带JVM与应用JDK分开。POST /api/attractions/synonym-search只接受以下契约，服务端固定索引、字段与分析器，浏览器不能上传任意DSL。预算不截断小数，q长度按UTF-16单位计。

package dev.esweb.travel;

import jakarta.validation.constraints.*;

public record SynonymInput(
        @NotBlank @Size(max = 60) String q,
        @NotNull @Pattern(regexp = "BJ|SY") String cityCode,
        @NotNull @Min(0) @Max(100000000) Integer maxPriceFen,
        @NotNull @Pattern(regexp = "plain|aliases|graph|phrase|loose|late") String mode) {
}
    public String analyzer(SynonymInput input) {
        return switch (input.mode()) {
            case "plain" -> "travel_plain";
            case "aliases" -> "travel_base";
            case "late" -> "travel_late";
            case "graph", "phrase", "loose" -> "travel_search";
            default -> throw new IllegalArgumentException("Unknown synonym mode");
        };
    }

    public SearchRequest request(SynonymInput input) {
        boolean phrase = input.mode().equals("aliases") || input.mode().equals("phrase");
        List<String> fields = input.mode().equals("aliases")
                ? List.of("name", "name_en", "aliases") : List.of("name", "name_en");
        return SearchRequest.of(s -> s.index(INDEX).size(20).trackTotalHits(t -> t.enabled(true)).trackScores(true)
                .query(q -> q.bool(b -> b.must(m -> m.multiMatch(mm -> {
                    mm.query(input.q()).fields(fields).analyzer(analyzer(input))
                            .type(phrase ? TextQueryType.Phrase : TextQueryType.BestFields);
                    if (phrase) mm.slop(0);
                    else mm.operator(Operator.And).autoGenerateSynonymsPhraseQuery(!input.mode().equals("loose"));
                    return mm;
                }))
                        .filter(f -> f.term(t -> t.field("city_code").value(input.cityCode())))
                        .filter(f -> f.term(t -> t.field("status").value("open")))
                        .filter(f -> f.term(t -> t.field("currency").value("CNY")))
                        .filter(f -> f.range(r -> r.number(n -> n.field("ticket_price_fen")
                                .gte(0.0).lte(input.maxPriceFen().doubleValue()))))))
                .sort(srt -> srt.field(f -> f.field("attraction_id").order(SortOrder.Asc))));
    }

两个诊断分析都处理当前输入，左侧基础链与右侧模式链并非读取历史词项。explain=true保留完整属性，再从最后一层提取positionLength。实际发现仅筛出positionLength会缺失9.4.8客户端模型要求的bytes/termFrequency；本课保留完整详细响应，不关闭客户端必填校验。分析请求和搜索请求逐份由Java返回，路径参数不在JSON body里，重放时仍须点名本课索引。

    public Result search(SynonymInput input) throws IOException {
        // Both analyses inspect supplied q. They do not read stored terms from existing documents.
        var base = AnalyzeRequest.of(a -> a.index(INDEX).analyzer("travel_base").text(input.q())
                .explain(true));
        var query = AnalyzeRequest.of(a -> a.index(INDEX).analyzer(analyzer(input)).text(input.q())
                .explain(true));
        var baseResponse = json.readTree(JsonpUtils.toJsonString(client.indices().analyze(base), client._jsonpMapper()));
        var queryResponse = json.readTree(JsonpUtils.toJsonString(client.indices().analyze(query), client._jsonpMapper()));
        var request = request(input);
        var response = client.search(request, SynonymAttraction.class);
        if (response.timedOut() || response.shards().failed().longValue() != 0 || response.hits().total() == null)
            throw new AttractionSearchService.IncompleteSearchException();
        var cards = response.hits().hits().stream().map(hit -> {
            var source = hit.source();
            if (source == null || !hit.id().equals(source.attractionId()) || source.name() == null
                    || source.nameEn() == null || source.aliases() == null || source.ticketPriceFen() == null
                    || source.cityCode() == null || source.currency() == null || source.status() == null)
                throw new AttractionSearchService.IncompleteSearchException();
            List<Object> sort = hit.sort().stream().map(v -> (Object) v._get()).toList();
            return new Card(hit.id(), source.name(), source.nameEn(), source.aliases(), source.cityCode(),
                    source.ticketPriceFen(), source.currency(), source.status(), hit.score(), sort);
        }).toList();
        return new Result(response.hits().total().value(), response.hits().total().relation().jsonValue(), response.took(),
                input, analyzer(input), json.readTree(JsonpUtils.toJsonString(base, client._jsonpMapper())),
                json.readTree(JsonpUtils.toJsonString(query, client._jsonpMapper())), baseResponse, queryResponse,
                tokens(baseResponse), tokens(queryResponse), json.readTree(JsonpUtils.toJsonString(request, client._jsonpMapper())), cards);
    }

完整服务还检查token属性、源字段和ID，保留完整分析链、名称/英文名/别名/城市/整数分/score/sort。输入非法400；缺索引等ES拒绝502；连接或transport异常503；搜索超时、分片失败或不完整字段502。后两类搜索不完整只有防护代码，本轮未构造真实执行超时/部分分片失败。正常0命中仍是200，不能清一色显示“服务断了”。

能力检查：先预测，再修改一个条件

1. 给bj-palace补“紫禁城”，餐厅也自动有了这个别名吗？

不会。aliases是该文档的普通text字段；别名查询仍可能匹配其他资料的原名，但不会给其他资料写入新别名。全局查询同义词则会让“故宫”名称也成为候选。

2. palace的positionLength=2，是否表示它有两个字符？

不是，它从位置0跨到位置2；另一条路径走forbidden、city两条边。字符串长度、UTF-16 offset和图中位置跨度是三件事。

3. 默认AND已经自动生成同义词短语，为什么bj-tail还在？

默认只让forbidden city这个多词同义分支相邻，museum仍是另一个必需子句。Forbidden City History Museum满足；完整phrase/slop0才排除中间的History。

4. 把繁简与lowercase放最后，最终文字相同，结果就相同吗？

不一定。同义词已经错过匹配时，后置归一不会倒带。实际late对PALACE museum为0，对故宮漏bj-wall；先统一输入与规则的形式再展开。

5. 皇城旧称重载后命中了旧文档，说明旧倒排重建了吗？

没有。本课只改查询路径；name原有基础词项与_source/版本保持不变。修改索引分析才需要明确重新写入或重建受影响资料；个别实体别名更新则改该资料并等待可见。

6. 独立将紫禁城/BJ/graph的预算改为0，预测全部ID。

只有bj-traditional。它免费却不符合宫殿游览意图；过滤条件正确和语义相关性正确是不同判断。让Java实际DSL重放REST，不能只数卡片。

7. 紫禁城/SY返回sy-palace，城市筛选坏了吗？

城市筛选正确排除了北京资料；同义词把紫禁城扩成故宫，仍误入当地另一景点。把精确实体别名、语言扩展与城市意图一起审核，不能简单删除城市条件。

实际陷阱

把同义词token全AND，或把默认同义词分支当作完整phrase。

先画position→position+length的路径，再核对真实改写与ID。自动短语false会引入隔词/反序候选，完整phrase又可能减少召回，按当前意图选择。

只转换查询，或认为分析链顺序不重要。

旧索引表达必须与查询形式兼容；后置转换不能让同义词重新匹配。本课保存原文与已存向量，不能用当前_analyze冒充历史词项。

把关系扩展当成实体认证，把更新JSON当成发布。

全局规则可能新增同名商户或跨意图景点；管理API实际PUT、完整集合与重载响应都要核对。别名更新与查询重载分别验收，清理先删引用索引。
